# Observability

Production-minded GenAI systems need visibility into model calls, retrieval, latency, cost and failures.

## Minimum Signals

- structured logs;
- correlation ID;
- request duration;
- model latency;
- retrieval latency;
- token usage;
- estimated cost;
- error logs.

## AI Request Log

The observability schema stores sanitized model-call telemetry in `genai.ai_request_logs`.
The log intentionally stores metadata, usage and retrieval references only. It does
not store full rendered prompts, response bodies, document chunk text, provider
credentials or API keys.

Stored fields:

- request ID;
- API version;
- optional user ID;
- optional tenant ID;
- correlation ID;
- provider;
- model;
- prompt template name;
- prompt template version;
- prompt template content hash;
- input tokens;
- output tokens;
- optional embedding tokens;
- estimated cost;
- latency;
- optional retrieval latency;
- retrieved document IDs;
- citation references;
- status;
- optional error code;
- created timestamp.

Status is normalized to `Succeeded` or `Failed`. Provider errors keep the
application-level error code when one is available, such as `rate_limited` or
`provider_unavailable`.

RAG request logs include retrieval latency plus document IDs and citation
reference IDs for the chunks that were included in the prompt. No-context RAG
outcomes are also logged after successful embedding and retrieval with no prompt
metadata and no retrieved document references. They do not store chunk text.

Indexing can abandon an in-flight embedding request after lease ownership is
lost or worker cancellation starts. If the provider later returns a successful
embedding response, the discarded response is still logged as embedding-only
usage with provider, model, correlation ID and embedding tokens so usage
summaries and cost accounting include potentially billable late responses. The
discarded indexing log entry keeps `status=Succeeded` because the provider call
returned successfully, but sets `error_code=indexing_abandoned` so cost reports
can distinguish billable discarded usage from ordinary successful calls. It does
not store prompt text, document content or retrieved document references.

## Failure Behavior

AI request logging defaults to fail-open telemetry. If the telemetry store is
unavailable after a model call succeeds, the application writes a structured
application log and continues returning the model result. If the model call
fails, the original provider exception is preserved and rethrown even when the
best-effort failure log cannot be persisted. Operators can set
`GenAIPlatform:Observability:AiRequestLogging:FailureMode` to `FailClosed` when
durable success/no-model request logs are a required audit record that must
block user-facing responses on write failure. The default value is `FailOpen`
for the starter-kit sample path.

Correlation IDs are validated or generated by the Application model gateway
request policy and then passed through API, Application, Infrastructure provider
adapters and persisted request logs.

## Fallback And Adapter Failure Events

These source-generated structured warning events make handled failures visible:

| Event ID | Event name | Fields |
|---|---|---|
| 4001 | `ExternalMcpToolExecutionFailed` | `ServerName`, `ToolName`, `ExceptionType` |
| 4002 | `AgenticBudgetFallbackUsed` | `ConversationId`, `CorrelationId`, `Reason`, `ExceptionType` |
| 5001 | `RagSearchInfrastructureFailure` | `ErrorCode`, `ExceptionType` |

Event 4001 covers exceptions swallowed by the external MCP tool wrapper, including
cancellation that was not requested by its caller. Server and tool names use a
sanitized ASCII diagnostic projection capped at 64 characters each. Caller
cancellation keeps its existing propagation and post-dispatch audit behavior.
Connection-manager lifecycle warnings continue to cover transport failures that
already return a typed unknown outcome; event 4001 does not replay those calls.

Event 4002 is emitted on the first budget fallback in each conversation, even
when multiple conversations share one dependency-injection scope. `ConversationId`
and the session's validated `CorrelationId` identify the conversation and request
that used the fallback. `Reason` is
`pricing_unavailable` for a missing estimate, or `estimator_failed` with the
exception type when estimation throws. Successful estimates and cancellation
produce no fallback warning. The existing demo fallback arithmetic is unchanged.

Event 5001 covers mapped PostgreSQL schema/query failures, other Npgsql failures
and timeouts. Its error code comes from the closed retrieval mapping. These three
events receive no exception object, raw message, SQL, prompt, document text,
embedding vector, credentials, tool arguments, schema or result payload.

Unexpected RAG programming errors propagate as their original exceptions.
The existing dispatcher warning 3002 owns their exception and stack logging;
they are not relabeled as retrieval availability errors. The new adapter warnings
do not duplicate that unhandled-exception stack record.

## Implemented Audit Records

The starter kit currently persists structured records for:

- sanitized AI model request logs;
- potentially billable discarded embedding responses;
- backend-controlled tool call audit logs.

## Later Audit Events

Additional sensitive actions should use the same durable-audit approach when
implemented:

- document uploaded;
- document deleted;
- prompt template changed;
- evaluation run executed;
- quota exceeded.
